# 디자인 구현 계획

## 화면 기준

[목업 폴더](mockups)의 색상, 카드 구조와 정보 배치를 참고합니다. 실제 데이터 길이, 선택 항목 수, 글자 크기에 맞춰 화면을 조정합니다. 세부 시각 규칙은 [UI 가이드라인](ui-guidelines.md)을 따릅니다.

| 영역 | 적용된 구성 | 점검할 항목 |
| --- | --- | --- |
| 시작 화면 | 브랜드 배경, 심볼, 캐릭터, 입력 카드 | 심볼 비율, 게스트 안내와 미지원 인증 구분 |
| 홈 | 대표 약속 카드, 주간 현황, 방 미리보기 | 긴 방 제목, 추천 없음, 목록 5개 제한 |
| 방 생성 | 입력 카드, 날짜·시간 선택, 정원 조절 | 키보드 표시, 작은 화면 스크롤, 오류 안내 |
| 방장 후보 | 공통 달력, 후보 칩, 시간대 카드, 선택 요약 | 후보 10개, 제외 칩, 월 이동, 선택 복원 |
| 초대 | 방 정보, 복사·공유, 참여 현황 | 긴 링크, 실제 인원, 다른 기기 참여 안내 |
| 방 상세 | 응답 현황, 추천 날짜·시간, 참여자, 확정 버튼 | 응답 없음, 추천 없음, 확정·마감 상태 |
| 참여자 응답 | 후보 달력, 선택 날짜, 시간대, 제외 날짜 | 허용 시간만 표시, 모든 후보 제외, 회전 |
| 참여자 목록 | 이니셜과 이름, 응답 상태, 추가 버튼 | 긴 이름, 정원 초과, 마감 후 비활성 |
| 캘린더 | 월 달력, 마감·확정 표시, 일정 목록 | 6주인 월, 일정 없는 월, 긴 일정 제목 |
| 채팅 | 방 목록, 이름 배지, 메시지, 공지 | 긴 메시지, 빈 채팅, 키보드와 입력창 |
| 알림·내 정보 | 텍스트 목록과 현황 카드 | 샘플 구분, 준비 중 메뉴, 실제 현황 |

## 개선 순서

1. 달력 날짜와 버튼의 터치 영역을 넓힙니다.
2. 작은 텍스트와 낮은 대비를 정리합니다.
3. 작은 화면과 글자 확대 상태의 겹침·잘림을 수정합니다.
4. 아이콘 접근성 설명과 선택·비활성 상태를 확인합니다.
5. 리소스 문구의 표현과 공통 스타일을 점검합니다.
6. 시스템 테마와 관계없이 밝은 테마를 유지하고 여러 화면 크기의 실행 캡처를 확인합니다.

## 화면 변경 확인

- 주요 동작을 텍스트와 선택 상태로 구분할 수 있습니다.
- 방 제목과 이름이 길어도 인원·마감·버튼이 가려지지 않습니다.
- 후보 개수와 응답 상태 변화에 맞춰 카드가 늘어나거나 빈 상태를 표시합니다.
- 폼은 키보드가 열린 상태에서도 완료 버튼에 접근할 수 있습니다.
- 실제 구현을 실행한 캡처로 간격과 잘림을 확인합니다.
- 기기 크기와 글자 크기별 확인 결과를 PR에 기록합니다.
