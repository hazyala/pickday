# 디자인 구현 계획

이 문서는 첨부 목업을 실제 Android 화면으로 옮기는 순서를 정의합니다.

PickDay에서 디자인 품질은 핵심 요구사항입니다. 기능이 동작하더라도 목업과 다르게 산만하거나, 간격과 곡률이 맞지 않거나, 사용성이 떨어지면 완료로 보지 않습니다.

## 디자인 우선순위

1. 화면은 깨끗하고 빠르게 읽혀야 합니다.
2. 카드를 기본 구조로 사용합니다.
3. 폰트 크기와 굵기를 일관되게 맞춥니다.
4. 주요 액션과 선택 상태는 퍼플을 사용합니다.
5. 아이콘은 행동 또는 상태를 명확하게 할 때만 사용합니다.
6. 방 목록, 프로필, 참여자 아바타의 장식용 이모지는 제거합니다.
7. 브랜드 캐릭터 이미지는 화면을 돕는 곳에만 사용합니다.
8. 장식보다 실제 데이터의 명확성을 우선합니다.

## 화면 구현 순서

### 1. Home

참고 목업:

- `03 Home.png`

먼저 하는 이유:

- 앱의 전체 시각 기준을 정하는 화면입니다.
- 방 카드, 응답률, 가능한 날짜, 하단 내비게이션 기준을 한 번에 잡을 수 있습니다.

디자인 작업:

- hero 카드를 목업처럼 부드럽고 정돈된 카드로 정리합니다.
- 방 목록 시각 요소를 단순화합니다.
- 방 row의 카테고리 이모지를 제거합니다.
- 알림과 추가 액션만 아이콘으로 유지합니다.
- 응답률과 마감을 가장 잘 보이게 합니다.

기능 작업:

- 방 목록을 Repository 데이터로 렌더링합니다.
- 방 ID 기준으로 Room Detail로 이동합니다.
- CTA/FAB에서 Create Meetup으로 이동합니다.

### 2. Create Meetup

참고 목업:

- `05 Create Meetup.png`

디자인 작업:

- 입력 폼을 카드 단위로 묶습니다.
- 텍스트 필드, 날짜/시간 선택, 인원 stepper, 공개 범위, 알림 토글을 일관되게 만듭니다.
- 캘린더, 공개 범위, 미리 보기, 다음 이동 아이콘만 필요한 경우 사용합니다.

기능 작업:

- 필수값을 검증합니다.
- 로컬 방 draft를 생성합니다.
- 제목, 설명, 마감, 인원 범위, 공개 범위, 알림 설정을 저장합니다.

### 3. Host Selection

참고 목업:

- `06 Selection.png`

디자인 작업:

- 날짜 chip과 시간대 카드를 터치하기 쉽게 정리합니다.
- 선택 상태를 명확하게 보여줍니다.
- 하단 선택 요약은 간결하지만 유용하게 유지합니다.

기능 작업:

- 후보 날짜를 저장합니다.
- 선택 시간대를 저장합니다.
- 제외 날짜가 있다면 함께 저장합니다.
- 화면 이동 후에도 상태를 유지합니다.

### 4. Invite Members

참고 목업:

- `07 Invite Members.png`

디자인 작업:

- 링크, 복사, 공유, QR, 알림 컨트롤은 아이콘을 사용합니다.
- 방 카테고리 장식 이모지는 사용하지 않습니다.
- 초대 방식은 명확한 row 구조로 정리합니다.

기능 작업:

- 로컬 초대 코드와 초대 링크를 생성합니다.
- 링크 복사를 지원합니다.
- Android share sheet로 공유합니다.
- 알림 토글 상태를 저장합니다.

### 5. Room Detail

참고 목업:

- `04 RoomDetail.png`

디자인 작업:

- 진행 현황, 유력한 날짜, 시간 선호도, 참여자 상태를 우선 배치합니다.
- 참여자 식별은 실제 이미지, 이니셜, 중립 placeholder를 사용하고 이모지를 쓰지 않습니다.
- 뒤로가기, 알림, 공유, 리마인더, 응답 CTA에는 필요한 아이콘만 사용합니다.

기능 작업:

- 방장/참여자 변형을 렌더링합니다.
- 응답 진행률을 보여줍니다.
- 계산된 일정 후보를 보여줍니다.
- 응답 수정으로 이동할 수 있게 합니다.
- 충분한 데이터가 있을 때 방장이 확정할 수 있게 합니다.

### 6. Participant Response Selection

참고 목업:

- `08 ResponseSelection.png`

디자인 작업:

- 전체 캘린더 느낌을 최대한 목업에 맞춥니다.
- 불가, 선택 가능, 선택됨 상태를 명확히 구분합니다.
- 시간대 선택은 카드형 UI로 유지합니다.

기능 작업:

- 참여자 응답을 저장합니다.
- 최대 날짜 선택 수를 제한합니다.
- 선택 날짜 제거와 응답 수정을 지원합니다.
- 다음 단계는 장소 입력 또는 완료 흐름으로 연결합니다.

### 7. Place Input And Result

참고 목업:

- 아직 최종 목업 없음

디자인 작업:

- 기존 카드 시스템을 따릅니다.
- 가능한 장소와 희망 장소 입력을 단순하게 구성합니다.
- 상위 결과는 순위와 확정 CTA가 분명하게 보이게 합니다.

기능 작업:

- 가능한 장소와 희망 장소를 저장합니다.
- 날짜, 시간, 장소 순위를 계산합니다.
- 최종 일정을 로컬에서 확정합니다.

## 화면별 완료 기준

화면 작업 완료 시 아래 기준을 확인합니다.

- 중요한 텍스트가 겹치지 않습니다.
- 주요 UI 의미를 이모지에 의존하지 않습니다.
- Primary action이 명확하게 보입니다.
- 빈 상태와 잘못된 입력 상태가 구현되었거나 문서에 pending으로 명시되어 있습니다.
- 간격과 곡률이 주변 화면과 일관됩니다.
- 아이콘은 절제되어 있고 기능적입니다.
- 일반적인 휴대폰 화면 크기에서 수동 테스트가 가능합니다.

## 아이콘 사용 결정

유지할 아이콘:

- 뒤로가기
- 알림
- 공유
- 복사
- 링크
- 캘린더
- 시계/마감
- 인원 수
- 체크/선택
- 추가
- 다음/화살표
- 미리 보기
- 정보

제거하거나 피할 아이콘:

- 방 목록 카테고리 아이콘
- 참여자 이모지 아바타
- 프로필 이모지 placeholder
- 빽빽한 영역의 반복 장식 아이콘

아이콘 없이도 명확하게 읽히는 UI는 아이콘을 쓰지 않는 쪽을 우선합니다.
