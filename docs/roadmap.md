# 개발 로드맵

## 구현된 기능

| 영역 | 구현 내용 |
| --- | --- |
| 방 관리 | UUID 기반 방 생성, 정원과 참여 인원 구분, 작성 중 정보 수정 |
| 후보 설정 | 마감일 이후 날짜 검증, 허용 시간대와 제외 날짜 반영 |
| 참여자와 응답 | 참여자 추가, 이름 중복·정원 검사, 응답 제출·수정·복원 |
| 일정 계산 | 날짜·시간별 가능 인원, 동점 정렬, 전원 가능 여부, 상관없음 처리 |
| 일정 확정 | 방장 확인, 미응답 안내, 홈·상세·캘린더 반영, 확정 후 수정 제한 |
| 화면 상태 | 방별 작성 중 선택 유지, 주요 작성 화면 회전 복원, 잘못된 방 ID 처리 |
| 채팅과 알림 | 방별 메모리 메시지, 참여·응답·확정 이벤트, 샘플 상태 요약 구분 |
| 코드 구조 | 독립 모델 13개, 샘플 공급자, 메모리 상태 저장소, 조회·변경 진입점 분리 |
| 화면 문구 | Activity·레이아웃 문자열 리소스, 동적 문구의 서식 문자열 |
| 화면 사용성 | 키보드 여백, 48dp 달력 행, 긴 제목 줄바꿈, 실제 사용자 통계, 공통 하단 탭 |
| 앱 진입 | 게스트 데모, 회원가입 화면 미리보기 |

데이터는 프로세스 안에서 유지합니다. 영구 저장과 백엔드 연결은 구현 범위에 포함하지 않습니다.

## 개선 우선순위

### 1. 화면 사용성

- 작은 화면과 글자 크기 확대 상태에서 입력 영역과 하단 버튼을 점검합니다.
- 달력 날짜, 칩, 아이콘 버튼의 터치 영역을 확보합니다.
- 작은 글씨, 대비, 접근성 설명을 정리합니다.
- 화면 문구의 표현과 공통 스타일을 점검합니다.
- 밝은 테마의 여러 기기 크기·가로 화면·TalkBack을 확인합니다.
- [UI 점검 결과](ui-review.md)의 확인 범위를 실제 기기로 확장합니다.

### 2. 저장소 구조

- 정적 `LocalMeetupRepository` 호출을 인스턴스 기반 저장소 인터페이스로 전환합니다.
- 네트워크 구현체가 같은 인터페이스를 사용할 수 있도록 오류와 결과 형식을 정합니다.
- 샘플 제공 여부를 저장소 초기화 설정으로 분리합니다.

### 3. 서버 연동

- [API 계약 초안](api-contract-draft.md)의 식별자와 요청·응답 형식을 확정합니다.
- 인증과 사용자별 접근 권한을 연결합니다.
- 초대 코드 참여와 여러 기기의 응답 동기화를 구현합니다.
- 네트워크 대기, 실패, 재시도 상태를 화면에 반영합니다.
- 실시간 채팅과 푸시는 서버 기능에 맞춰 추가합니다.

### 4. 서비스 확장

- 방 종료와 채팅 보관 정책을 정의합니다.
- 알림 읽음 상태, 사용자 설정, 프로필 편집을 구현합니다.
- 장소 후보 입력과 추천 규칙을 설계합니다.
- 영구 저장이 필요해지면 저장 범위와 복원 정책부터 정합니다.

## main 병합 기준

- 방 생성 → 후보 설정 → 참여자 응답 → 추천 → 확정을 한 기기에서 완료할 수 있습니다.
- 마감, 정원, 중복 이름, 잘못된 후보와 확정 후 수정 제한을 검증합니다.
- 홈·상세·캘린더의 일정과 가능 인원이 일치합니다.
- 응답이 없거나 가능한 일정이 없을 때 해당 상태를 표시합니다.
- 게스트, 샘플 데이터, 미지원 기능을 화면과 문서에서 구분합니다.
- 빌드, 단위 테스트, 기기 테스트를 통과하고 lint 오류가 없습니다. 남은 경고는 검토합니다.
- 화면 변경에는 실행 캡처와 수동 점검 결과를 남깁니다.
