# PickDay 로드맵

이 문서는 현재 `dev` 브랜치의 개발 목표를 정의합니다. 이번 목표는 백엔드를 바로 배포하는 것이 아니라, Android 앱이 서버 연동 직전 수준까지 로컬에서 완성되도록 만드는 것입니다.

## Dev 목표

PickDay를 서버 연동 직전 Android 앱 상태로 만듭니다.

- 현재 카드형 UI와 화면 톤은 유지하고, 기능 동작만 실제 데이터 기반으로 고칩니다.
- 로컬에서 약속 방을 생성할 수 있어야 합니다.
- 초대 링크 또는 초대 코드를 복사하고 공유할 수 있어야 합니다.
- 날짜, 시간, 제외 날짜를 입력할 수 있어야 합니다.
- 달력은 2025년 5월 고정이 아니라 현재 월, 선택 월, 방 후보 날짜 범위를 기준으로 렌더링되어야 합니다.
- 입력된 로컬 데이터를 기반으로 최적 일정을 계산할 수 있어야 합니다.
- 방 상세에서 진행 현황, 참여자 상태, 후보 일정, 확정 일정을 볼 수 있어야 합니다.
- 이후 Retrofit/API Repository를 붙여도 화면 구조를 다시 만들 필요가 없어야 합니다.
- 첨부 목업 수준의 디자인 완성도를 유지해야 합니다.
- 신규 화면 확장은 이미 추가된 알림 목록, 후속 방 채팅, 내 정보 화면 범위로 제한합니다.
- 로그인과 회원가입은 인증 전 화면 stub으로 제공하며, 실제 계정 생성/세션 처리는 백엔드 연동 단계에서 붙입니다.

## 이번 목표에서 제외하는 것

- 운영 서버 배포
- 실제 Google/Kakao 로그인
- 실제 이메일 로그인/회원가입
- 실제 푸시 알림
- 실제 Kakao SDK 공유
- 실제 캘린더 Provider 연동
- 결제, 분석, 관리자 기능
- 방 채팅과 내 정보 외의 신규 화면 확장

위 항목은 UI 자리나 로컬 stub은 둘 수 있지만, 실제 구현된 것처럼 문서나 화면에서 과장하지 않습니다.

## 마일스톤

### M0. 문서 기준선

- 로드맵, 워크플로우, UI 가이드, 화면 흐름, 데이터 모델, API 초안을 추가합니다.
- 브랜치와 커밋 규칙을 정의합니다.
- 아이콘과 이모지 사용 기준을 정의합니다.
- 서버 연동 직전 완료 기준을 정의합니다.

### M1. 디자인 시스템 정리

- 색상, 폰트, 곡률, 그림자, 간격, 카드 스타일을 목업에 맞춥니다.
- 필요한 버튼/액션 이모지만 벡터 아이콘으로 정리합니다.
- 방 목록과 프로필 영역의 장식용 이모지를 제거합니다.
- 주요 버튼, 보조 버튼, 카드, 칩, 토글, 진행률, 하단 내비게이션을 표준화합니다.

### M2. 로컬 도메인 모델

- 사용자, 방, 참여자, 응답, 일정 결과, 확정 일정, 알림, 사용자 설정 모델을 추가합니다.
- Activity에 직접 박힌 더미 문자열을 모델 기반 렌더링으로 바꿉니다.
- 샘플 데이터는 Repository 또는 Fixture 계층에만 둡니다.
- Home, Room Detail, Selection, Response Selection은 같은 Repository 데이터를 바라보게 합니다.

### M3. 로컬 방 생성 흐름

- Create Meetup에서 입력한 값을 실제 로컬 방 객체로 저장합니다.
- Selection, Invite, Home, Room Detail이 같은 방 데이터를 바라보게 합니다.
- 필수값 검증과 빈 상태, 오류 상태를 처리합니다.

### M4. 로컬 응답 입력 흐름

- 참여자의 날짜/시간 선호도를 저장합니다.
- 응답 상태를 로컬에 저장하고 수정할 수 있게 합니다.
- 후보 날짜와 제외 날짜는 고정 5월 값이 아니라 방 데이터와 현재 달력 상태에 맞게 표시합니다.

### M5. 최적 일정 계산 엔진

- 일정 점수 계산을 Activity 밖으로 분리합니다.
- 전원 교집합 날짜를 우선 후보로 표시합니다.
- 날짜와 시간 후보를 순위화합니다.
- 동점, 빈 응답, 일부 응답, 전원 응답 케이스를 테스트합니다.

### M6. 방 상세와 확정 흐름

- 참여 완료율과 미응답 인원을 표시합니다.
- 가장 유력한 날짜, 시간 선호도, 참여자 상태를 표시합니다.
- 방장이 최종 일정을 로컬로 확정할 수 있게 합니다.
- 확정 상태가 Home과 Room Detail에 반영되게 합니다.

### M7. 알림과 내 정보 화면

- Home 상단 알림 버튼에 대응하는 알림 목록 화면을 추가합니다.
- 하단 내비게이션의 알림 탭은 이후 방 채팅 진입점으로 전환합니다.
- 하단 내비게이션의 내 정보 탭에 대응하는 사용자 정보 화면을 추가합니다.
- 두 화면은 현재 UI 톤을 유지하며, 실제 인증/푸시 연동 전에는 로컬 데이터를 사용합니다.
- 알림 화면의 빈 상태, 모두 읽음, 읽음/안읽음 저장은 후속 범위로 둡니다.

### M8. 백엔드 연동 준비

- API 초안을 기준으로 Retrofit 인터페이스를 정의합니다.
- Local Repository와 Remote Repository를 교체 가능한 구조로 만듭니다.
- 이메일 로그인/회원가입, 인증, 네트워크 실패, 서버 오류 상태를 화면과 문서에 반영합니다.
- 남은 백엔드 연동 작업을 명확하게 문서화합니다.

## 백엔드 작업 전 완료 기준

- 서버 없이도 온디바이스에서 핵심 흐름을 끝까지 수행할 수 있어야 합니다.
- 주요 의미를 이모지에 의존하지 않아야 합니다.
- 주요 화면의 빈 상태, 정상 상태, 오류 상태 또는 미구현 상태가 문서화되어야 합니다.
- 문서와 실제 동작이 일치해야 합니다.
- 빌드와 관련 테스트가 통과해야 합니다.
