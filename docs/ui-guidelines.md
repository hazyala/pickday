# UI 가이드라인

PickDay는 디자인이 핵심 경쟁력인 앱입니다. 화면은 간단해야 하지만, 동시에 예쁘고 정돈되어 있어야 합니다.

현재 dev 사이클의 주요 시각 기준은 첨부 목업입니다. 다만 목업은 분위기, 정보 위계, 색감, 카드 감각을 참고하기 위한 자료이며 픽셀 단위 정답이 아닙니다. 실제 서비스에서 데이터가 없거나 아직 계산되지 않은 상태를 꾸며서 채우지 않는 것을 우선합니다.

현재 정리된 UI는 유지합니다. 이후 작업은 색감과 레이아웃을 다시 바꾸는 것이 아니라, 고정 달력과 더미 통계를 실제 데이터 기반 기능으로 교체하는 데 집중합니다.

## 시각 방향

깨끗한 파스텔 카드형 UI를 사용합니다.

- 배경은 거의 흰색에 가까운 부드러운 톤을 사용합니다.
- 주요 액션과 선택 상태는 퍼플을 중심으로 합니다.
- 라벤더, 핑크, 민트, 블루는 보조 강조색으로만 사용합니다.
- 곡률은 크지만 과하지 않게 일관되게 유지합니다.
- 그림자는 강하게 쓰기보다 얇은 border와 표면 대비를 우선합니다.
- 폰트 크기, 굵기, 간격으로 정보 위계를 명확하게 만듭니다.
- 브랜드 캐릭터와 의미 있는 상태 표현 외의 장식은 줄입니다.
- 서버 데이터가 비어 있는 초기 상태에서는 기존 방, BEST, 응답률 같은 샘플 값을 노출하지 않습니다.

## 타이포그래피

앱 전체에서 같은 폰트 체계를 유지합니다.

- 화면 제목: 굵고 크게, 줄 간격은 단단하게
- 섹션 제목: 굵고 읽기 쉽게
- 본문: Regular 또는 Medium
- 보조 정보: 작은 크기와 부드러운 색상
- 버튼: 빠르게 읽히는 굵기

하나의 카드 안에서 너무 많은 폰트 굵기를 섞지 않습니다.

## 카드

카드는 PickDay 화면의 기본 구조입니다.

- 정보 그룹, 폼, 리스트, 결과 후보, 진행 상태는 카드로 묶습니다.
- 카드 곡률은 화면 종류별로 일관되게 유지합니다.
- 흰색 또는 아주 연한 라벤더 표면을 우선합니다.
- 진짜 컨트롤이 아닌 경우 카드 안에 또 카드를 중첩하지 않습니다.
- 무거운 그림자보다 여백, border, 배경 대비로 깊이를 만듭니다.

## 버튼과 컨트롤

Primary 버튼:

- 단계를 완료하거나 다음으로 이동하는 경우 전체 너비를 우선합니다.
- 퍼플 배경과 흰색 텍스트를 사용합니다.
- pill 또는 큰 rounded rectangle 형태를 사용합니다.
- 필요할 때만 오른쪽 화살표 아이콘을 둡니다.

Secondary 버튼:

- 흰색 또는 투명 배경을 사용합니다.
- 퍼플 border 또는 퍼플 텍스트를 사용합니다.
- 미리 보기, 상세 보기, 공유, 복사 같은 보조 행동에 사용합니다.

칩과 선택 카드:

- 선택 상태는 퍼플 fill, border, check mark 중 하나 이상으로 명확하게 보여줍니다.
- 이모지만으로 선택 상태를 표현하지 않습니다.

## 아이콘 정책

아이콘은 행동이나 상태를 빠르게 이해하게 만드는 경우에만 사용합니다.

사용 권장:

- 뒤로가기
- 다음/화살표
- 추가
- 캘린더
- 시계/마감
- 인원 수
- 공유
- 복사
- 링크
- 알림/리마인더
- 체크/선택됨
- 닫기/삭제
- 정보/도움말
- 미리 보기

사용 지양:

- 방 목록의 카테고리 장식
- 참여자 아바타
- 프로필 placeholder
- 의미 없는 장식 라벨
- 빽빽한 리스트 안의 반복 장식

방 카드는 제목, 참여자 수, 마감, 응답률, 상태를 중심으로 보여줍니다. 추후 카테고리 시각화가 필요하면 이모지가 아니라 통제된 이미지/카테고리 시스템으로 설계합니다.

## 데이터와 빈 상태

더미 데이터는 개발 중 레이아웃 확인용 샘플입니다. 실제 서비스 상태에서는 서버 또는 로컬 Repository가 반환한 데이터만 표시합니다.

- 신규 사용자의 Home에는 진행 중 약속, 가능한 날짜, 내 약속 방이 없을 수 있습니다.
- BEST 날짜는 충분한 응답 또는 계산 결과가 있을 때만 표시합니다.
- 응답률은 방 데이터가 있을 때만 표시합니다.
- 빈 상태는 방 만들기 CTA와 짧은 안내 문구로 처리합니다.
- 화면을 풍성하게 보이게 하려고 샘플 방이나 샘플 응답률을 자동 생성하지 않습니다.

## 이모지 정책

이모지는 최종 서버-ready UI에서 주요 UI 자산으로 사용하지 않습니다.

임시 허용:

- 기능 의미를 담당하지 않는 짧은 친근한 문구
- 목업과 정서가 맞고 제거 예정임이 명확한 경우

최종 UI에서 금지:

- 방 목록 카테고리 아이콘
- 프로필 또는 참여자 아바타
- 상태 표시
- 벡터 아이콘이 존재하는 버튼
- 캘린더 또는 선택 상태

## 캐릭터 에셋

목업의 캐릭터 이미지는 PickDay의 브랜드 분위기를 만드는 핵심 자산입니다. 캐릭터는 장식용 이모지나 방 카테고리 아이콘과 다르게 취급하며, 기존 캐릭터 에셋은 앱의 첫인상과 친근한 톤을 만드는 위치에서 최대한 유지합니다.

사용 권장:

- Splash/Login의 브랜드 순간
- Home hero
- Home의 진행 중 약속 카드와 방 만들기 CTA
- 방 만들기와 초대 화면의 상단
- 공간이 충분한 empty/friendly state

사용 지양:

- 빽빽한 방 목록 내부
- 실제 프로필 이미지가 아닌 참여자 식별 용도
- 폼 입력 집중을 방해하는 위치

## 화면 밀도

앱은 단순해야 하지만 허전하면 안 됩니다.

- 주요 액션은 항상 명확하게 보이게 합니다.
- 폼 섹션은 카드로 묶어 인지 부담을 줄입니다.
- 긴 설명보다 짧은 라벨과 즉각적인 피드백을 우선합니다.
- 한 화면에서 사용자가 지금 무엇을 해야 하는지 바로 알 수 있어야 합니다.

## 접근성과 사용성

- 터치 영역은 최소 44dp 이상을 목표로 합니다.
- 중요한 텍스트는 낮은 대비의 파스텔색에만 의존하지 않습니다.
- 선택됨, 비활성, 대기, 오류 상태는 시각적으로 구분되어야 합니다.
- 아이콘은 텍스트 라벨 또는 충분한 주변 맥락을 가져야 합니다.
- 색상만으로 의미를 전달하지 않습니다.
