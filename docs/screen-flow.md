# 화면 흐름

이 문서는 서버 연동 직전 Android 앱의 목표 화면 흐름을 정의합니다.

현재 UI는 유지하고 기능만 실제 데이터 기반으로 교체합니다. 새 화면을 계속 늘리는 것이 아니라, 기존 Activity 안의 5월 고정 달력, 더미 통계, 하드코딩된 방/응답 값을 Repository 데이터와 계산 결과로 바꾸는 것이 우선입니다.

## 핵심 흐름

1. Splash
2. Login 또는 Signup
3. Home
4. Create Meetup
5. Host Selection
6. Invite Members
7. Room Detail
8. Participant Response Selection
9. Notifications
10. Chat
11. My Info

Notifications는 Home 상단 알림 버튼에서 진입하는 로컬 알림 목록 화면으로 제공합니다. 하단 내비게이션의 방 채팅 탭은 채팅 방 목록 화면으로 이동합니다. 내 정보 화면은 추가 구현 대상으로 남겨둡니다.

## 화면별 기준

### SCR-01 Splash

목적:

- PickDay 브랜드를 보여주고 Login 또는 Home으로 이동합니다.

서버-ready 기준:

- 로컬 세션 상태에 따라 다음 화면을 결정합니다.
- 네트워크가 없어도 막히지 않아야 합니다.

### SCR-02 Login

목적:

- 이메일과 비밀번호 입력 화면을 보여주고 앱 진입을 시작합니다.
- 실제 인증 연동 전까지 로그인 버튼은 Home으로 이동하는 화면 stub으로 둡니다.
- 회원가입 링크는 Signup 화면으로 이동합니다.

서버-ready 기준:

- 실제 인증이 붙기 전까지 입력값 검증과 세션 발급이 구현된 것처럼 보이지 않아야 합니다.
- Google/Kakao UI가 있다면 계획된 연동임을 명확히 합니다.

### SCR-02A Signup

목적:

- 이름, 이메일, 비밀번호, 비밀번호 확인 입력 화면을 보여줍니다.
- 실제 회원가입 연동 전까지 회원가입 버튼은 Home으로 이동하는 화면 stub으로 둡니다.
- 로그인 링크와 뒤로가기는 Login 화면으로 돌아갑니다.

서버-ready 기준:

- 실제 인증이 붙기 전까지 계정 생성, 중복 확인, 비밀번호 정책 검증이 구현된 것처럼 보이지 않아야 합니다.
- 추후 API 연동 시 입력값 검증, 오류 문구, 세션 저장 흐름을 추가할 수 있어야 합니다.

### SCR-03 Home

목적:

- 진행 중인 약속, 가능한 날짜, 내 약속 방을 보여줍니다.

서버-ready 기준:

- Repository 데이터로 방 목록을 렌더링합니다.
- 방 목록의 장식용 이모지를 제거합니다.
- 방 제목, 참여자 수, 마감, 응답률, 상태를 보여줍니다.
- 신규/빈 데이터 상태에서는 기존 방, BEST 날짜, 응답률을 임의로 만들지 않습니다.
- 진행 중 약속이나 방 목록이 없으면 빈 상태와 방 만들기 CTA를 보여줍니다.
- 가능한 날짜, BEST, 응답률, 마감 D-day는 고정 문자열이 아니라 실제 방/응답 데이터에서 계산합니다.
- 방 만들기 CTA가 Create Meetup으로 이동합니다.

### SCR-04 Create Meetup

목적:

- 방장이 약속 방을 생성합니다.

서버-ready 기준:

- 제목, 마감, 인원 제한을 검증합니다.
- 로컬 방 draft를 저장합니다.
- 다음 단계로 이동하면 생성한 방을 런타임 로컬 방 목록에 등록합니다.
- 생성한 방은 Chat의 방 목록에서 확인할 수 있어야 합니다.
- 공개 범위와 알림 설정을 모델 필드로 저장합니다.
- 다음 화면은 방장 날짜/시간 선택입니다.

### SCR-05 Host Selection

목적:

- 방장이 후보 날짜와 시간대를 선택합니다.

서버-ready 기준:

- 후보 날짜를 저장합니다.
- 선택 시간대를 저장합니다.
- 제외 날짜를 지원하는 경우 함께 저장합니다.
- 달력은 2025년 5월 고정이 아니라 현재 월, 선택 월, 방 후보 날짜 범위를 기준으로 표시합니다.
- 초대 화면으로 이동하기 전 선택 요약을 보여줍니다.

### SCR-06 Invite Members

목적:

- 초대 링크/코드를 공유하고 초기 참여 상태를 확인합니다.

서버-ready 기준:

- 안정적인 로컬 초대 코드와 링크를 생성합니다.
- 링크 복사를 지원합니다.
- Android share sheet로 공유합니다.
- 참여자 알림 토글을 로컬에 저장합니다.
- 링크, 공유, 복사, 알림 아이콘은 의미 있는 위치에만 사용합니다.

### SCR-07 Room Detail

목적:

- 방 상태, 응답 진행률, 유력 후보, 참여자 상태, 다음 액션을 보여줍니다.

서버-ready 기준:

- 방장/참여자 화면 변형을 렌더링합니다.
- Repository 데이터로 완료/미완료 인원을 계산합니다.
- 일정 계산 결과로 가장 유력한 날짜를 보여줍니다.
- 시간 선호도 순위를 보여줍니다.
- 참여자 상태는 이모지 아바타 없이 표시합니다.
- 통계는 화면에 적힌 숫자를 유지하는 것이 아니라 참여자 응답이 바뀔 때 다시 계산되어야 합니다.
- 실제 push가 없으면 리마인더는 로컬 stub으로 명확히 둡니다.

### SCR-08 Participant Response Selection

목적:

- 참여자가 가능한 날짜, 시간대, 제외 날짜를 선택합니다.

서버-ready 기준:

- 응답을 로컬에 저장합니다.
- 응답 수정을 지원합니다.
- 선택 개수 제한을 지킵니다.
- 캘린더 날짜와 제외 날짜는 고정 샘플이 아니라 방의 후보 날짜와 응답 가능 범위에서 생성합니다.
- 선택 상태를 이모지 없이 명확하게 보여줍니다.

### SCR-09 Notifications

목적:

- Home 상단 알림 버튼에서 약속 방 관련 알림을 확인합니다.
- 알림은 오늘, 이번 주, 이전 섹션으로 나누어 텍스트 목록 중심으로 표시합니다.

현재 구현 기준:

- `DummyDataSource.getNotifications()`의 로컬 더미 데이터로 응답 완료, 마감 임박, 일정 확정, 초대, 댓글 알림을 표시합니다.
- 각 항목은 제목, 연결된 방 이름, 선택 보조 문구, 발생 시각을 표시합니다.
- 뒤로가기로 Home으로 돌아갑니다.
- 하단 내비게이션의 방 채팅 탭은 알림 화면이 아니라 Chat 화면으로 이동합니다.

서버-ready 기준:

- 실제 push 연동 전까지는 로컬 이벤트/알림 목록을 표시합니다.
- 새 참여자, 응답 완료, 마감 임박, 일정 확정 같은 이벤트를 방 데이터에서 만들 수 있어야 합니다.
- 알림이 없으면 빈 상태를 보여줍니다.
- 읽음/안읽음 상태를 로컬에 저장합니다.

### SCR-10 Chat

목적:

- 하단 내비게이션의 방 채팅 탭에서 참여 중인 약속 방의 채팅 진입 목록을 보여줍니다.

현재 구현 기준:

- `DummyDataSource.getMyMeetupRooms()`의 기존 약속 방 더미 데이터를 사용해 방 목록을 표시합니다.
- Create Meetup에서 새 방을 생성하면 런타임 로컬 방 목록에 추가된 방도 함께 표시합니다.
- 방 목록에는 방 제목, 참여자 수, 마감, 응답률을 표시합니다.
- 방 목록 미리보기는 해당 방의 마지막 더미 채팅 메시지를 표시합니다.
- 참여 중인 방과 종료된 방 탭을 전환할 수 있습니다.
- 현재 종료된 방 더미 데이터는 없으므로 종료된 방 탭은 빈 상태를 표시합니다.
- 방을 선택하면 선택한 방 제목을 전달해 Chat Detail 화면으로 이동합니다.
- Chat Detail은 `DummyDataSource.getChatMessages()`의 더미 메시지 목록을 표시합니다.
- 메시지에는 이모지나 이미지 프로필 대신 발신자 이름 첫 글자 원형 배지를 표시합니다.
- 발신자 이름은 메시지 버블 밖에 표시합니다.
- 상단 공지 카드는 기존 방 데이터에서 참여자 수, 응답률, 마감 정보를 가져와 표시합니다.
- 더미 메시지는 음식과 장소 후보를 정하는 대화로 구성하고, 날짜와 시간 조율 대화는 넣지 않습니다.
- 입력창은 실제 텍스트 입력이 가능한 필드와 전송 버튼만 표시합니다.
- 전송 버튼은 현재 화면에 내 메시지를 로컬로 추가합니다.
- 첨부파일, 이모티콘 입력, 좋아요 기능은 표시하지 않습니다.

서버-ready 기준:

- 공통 room ID를 전달해 실제 방 채팅 스레드를 열 수 있어야 합니다.
- 참여 중, 종료됨 같은 방 상태는 더미 분기가 아니라 모델 상태에서 결정해야 합니다.
- 실제 메시지 전송, 읽음/안읽음, 전송 실패 상태를 단계적으로 추가합니다.
- 종료된 방에서는 입력 가능 여부와 보관 정책을 명확히 표시합니다.

### SCR-11 My Info

목적:

- 하단 내비게이션의 내 정보 탭에서 사용자 정보를 확인합니다.

서버-ready 기준:

- 실제 인증 전까지는 로컬/게스트 사용자 정보를 표시합니다.
- 이름, 프로필 placeholder, 알림 기본 설정 같은 앱 내부 설정을 보여줍니다.
- 계정 동기화가 구현되지 않았다면 구현된 것처럼 표시하지 않습니다.
- 로그아웃 또는 로컬 데이터 초기화 동작은 명확한 확인 과정을 둡니다.

## 내비게이션 규칙

- Create, Invite, Detail에서 뒤로가기를 눌렀을 때 저장된 로컬 상태가 예기치 않게 사라지면 안 됩니다.
- 하단 primary 버튼은 다음 단계로 이동합니다.
- 미리 보기, 상세 보기 같은 secondary 액션은 데이터를 변경하지 않습니다.
- 공통 상태 저장 구조가 생기기 전까지는 room ID를 화면 간에 전달합니다.

## 빈 상태와 오류 상태

주요 화면은 아래 상태를 순차적으로 정의합니다.

- 빈 상태
- 정상 상태
- 잘못된 입력 상태
- 로컬 fallback 상태
- API 연동 이후 서버 오류 상태
